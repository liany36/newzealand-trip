# 产出格式契约

三个格子必须产出一模一样的目录结构，这样评分时能直接对比同名文件，而且整份 `answers/` 可以被原样扔上静态站点。

```
answers/
├── meta.json          必填，见下
├── 1/                 任务 1（图纸 → 3D 房间）
│   ├── index.html     入口，相对路径，双击或静态服务器都能开
│   ├── out.glb        导出模型
│   ├── out.obj        导出模型（给 Unity 用）
│   ├── unity.png      你可以不做——由评分人事后自己导一次
│   └── README.md      怎么跑 + Unity/UE5 导入说明
├── 2/                 任务 2（后端体检）
│   ├── FINDINGS.md    按模板
│   └── patched/       改好的代码
├── 3/                 任务 3（场景渲染）
│   ├── index.html     打开就动
│   └── README.md      100 字物理自检
└── DELIVERY.md        总交付说明
```

## meta.json

```json
{
  "cell": "A",
  "tasks": ["1", "2", "3"],
  "notes": "最多 3 条技术前提"
}
```

## DELIVERY.md 必须回答六件事

```markdown
## 1. 每个任务：做了什么、怎么跑
## 2. 哪个任务没做完，做到哪一步
## 3. 90 分钟怎么分配的，为什么这么砍
## 4. 我做的关键假设（最多 5 行）
## 5. 我自己认为最弱的一环（1 行）
## 6. 如果还有 1 小时，我先做哪件事（1 行）
```

第 3 条是这题的核心之一：**预算不够时先保哪个**，比"全都做一半"更能看出判断力。

## 不许做的事

- 不许写"作为 AI 语言模型我……"之类自述
- 不许只给伪代码或说明文档，必须有能跑的东西
- 不许把测试数据写死让演示好看（发现按 0 分算）
- 不许用绝对路径。这些文件会原样传到公网域名上，`C:\Users\...` 一进页面就是白屏
- 不许问评分人问题——假设写进 DELIVERY.md 第 4 条
