# 任务 1 · 图纸 → 可摆家具的三维房间 → 导出引擎可用的模型

你是被一家做室内数字孪生的小公司临时雇来的。他们手上只有设计师给的一张 SVG 平面图，老板要的东西很具体：

> "我要能打开、能像摆积木一样把桌椅柜子拖进去、最后能导出成 Unity 和 UE5 都能吃掉的文件。
> 别给我 PPT，也别给我一个只能看的 3D 模型。"

## 输入

`../_shared/assets/floorplan.svg`

- 单位换算：SVG 里 **100 个单位 = 1 米**
- `class="wall"` 是墙，`class="door"` 是门洞（**门洞处必须没有墙**），`class="window"` 是窗
- 房间上标了名字（办公区 / 会议室 / 储物间），墙厚忽略不计，按中心线算

## 必须做到的（会被逐条验收）

1. **解析图纸**：把 SVG 读进去算出房间尺寸。界面上显示 `总宽 6.00 m × 总深 4.00 m`（数字必须是从 SVG 算出来的，不许写死）。
2. **三维房间**：墙体按实际平面升起（建议墙高 2.8 m），门洞处断开，窗按半透明蓝色面片贴在墙上（不要求开洞）。
3. **摆放**：左侧有家具面板，至少三类——桌子、椅子、柜子。从面板拖进场景，落到地面上。
4. **拖动**：已经放下的家具能用鼠标拖动改位置，松手位置要留住。
5. **微调**：选中家具后，方向键 ±10 cm，`R` 键旋转 15°。
6. **撤销**：一个按钮回到"刚导入图纸"的状态（清掉所有家具）。
7. **导出 glb**：一个按钮导出 `out.glb`（glTF 2.0 binary），浏览器下载。
8. **导出 obj**：再导一份 `out.obj` + `out.mtl`。Unity 原生只认 obj/fbx，glb 得先装 glTFast——这份是给 Unity 验的，别省。
9. **不要开 Unity。** 开了会吃掉你大半预算。你只负责把 `out.obj` 导出来，Unity 那边有人验。
10. **README.md**：怎么跑（3 行）、Unity 怎么导入、UE5 怎么导入，并说清两者差异（UE5 原生不吃 glTF，要插件或 Datasmith，这条写错会扣分）。

## 硬约束（违反即不合格）

- **不许用构建工具**。不能 `npm install`、不能 vite/webpack。必须是一个双击 `index.html` 或起个静态服务器就能跑的东西。CDN 引 three.js 可以。
- **家具几何全部程序化生成**，不许下载外部模型文件。
- 不许把尺寸、墙体坐标写死成常量来绕开解析——评分人会改一个墙的坐标重跑。
- **全部相对路径**。这份产物会被原样传到公网域名上，写死 `C:\Users\...` 或 `file://` 就等于白屏。

## 加分项（没有也不扣，但会影响"敢不敢交给客户"这一维）

- 家具不能穿墙 / 不能叠放在一起时给个提示
- 拖拽时有吸附网格
- 导出前能看到"将导出 N 个物体"的清单
- 载入一张新图纸不用刷新页面

## 你会怎么被评

一批硬指标会被机械地过一遍（能不能打开、墙数对不对、glb 能不能通过校验、节点数对不对），
另外一部分是主观的：一个真实用户愿不愿意把这个东西发给他自己的客户。

时间自己控制。先让它能跑，再让它好看。**没做完的部分写进 DELIVERY.md 第 2 条，诚实列不扣分。**
